# ASS Workbench：界面重分区与代码评估

检查基线：main `1c2b2d68de6ad8baba14a64bf387a923474661a8`，0.29.0。附件 2026-09-28 报告描述的是 0.13，不能作为当前缺失功能清单。评估依据是源代码、调用关系与现有测试；未进行用户设备实测。本文不把“存在代码”视为“真机可靠”。

## 结论

基本字幕编辑闭环已形成，现有能力足够支持日常 ASS 编辑和多种复杂排版。主要问题是界面入口缺乏层次、复杂工具密度失衡、若干功能只有领域模型或初步编辑器，以及验证覆盖与功能增长不一致。当前不宜宣称实现完整 Aegisub 或已经达到 1.0 全部验收条件。

扩展基础具备：纯 Kotlin 领域模块、独立字体/容器模块、canonical ASS 文档、Undo 与临时预览分离，以及工具实例与布局状态分离。扩展瓶颈也明确：约四千行的主界面文件、约两千五百行的 ViewModel、局部工具仍隐式依赖当前焦点，以及工程资源不可完整迁移。

## 全部界面职责分配

| 区域 | 主职责 | 工具 / 操作 | 归属边界 |
| --- | --- | --- | --- |
| 顶部全局操作 | 文档生命周期与历史 | 打开、保存、另存、撤销、重做、搜索 | 不放参数编辑；导入字体可保留文件操作快捷入口 |
| 参考预览 | 播放、同步、视觉检验 | 参考视频、播放头、直接操作 | 视频与 ASS 独立；最终视觉权威仍为 libass |
| 字幕列表 | 导航与选择 | 行、搜索结果、多选、跳转 | 不另建重复正文编辑器；点行打开统一检查器 |
| 字幕编辑 | 内容与事件结构 | 正文、事件结构、批量规则 | 原始 ASS 文本完整可见；单条结构与批量作用域分开 |
| 时间与同步 | 时间坐标 | 时间轴、帧时间 | 毫秒/波形与 CFR/VFR 帧模型有区别，不合并成一个“帧率”参数 |
| 排版与动画 | 视觉语义 | 样式、位置与几何、效果与动画、Karaoke、已有矢量裁剪 | Style 基值与 Event override 明确分层 |
| 字体资源 | 可用资源与实际需求 | 字体管理、字体依赖 | 文件库存与 ASS 的请求清单不同；同组但不是同一功能 |
| 检查与诊断 | 文档问题和运行证据 | 质量检查、兼容性、运行诊断 | Linter、播放环境风险、渲染日志各有对象，不重复贴“诊断”标签 |
| 工程与输出 | 工程上下文和容器 | 工程与封装、工具目录；全局文件菜单提供 ASS/SRT/.asswb 保存 | MKV 是字幕容器桥接，不扩张为视频压制 |

“工具目录”是跨区域检索入口，不是新的功能复制。所有工具只有一份分类元数据，固定布局与 Canvas 共用。现有序列化工具 key 不改名，旧工具实例与布局仍可恢复。

## 密度与布局变更

基线宽屏布局将约 57.5% 宽度给预览，字幕列表约 19.6%，参数面板约 23%。在 900dp 下列表不足 180dp，复杂表单挤在约 200dp 面板中。手机端同时堆叠预览、150–230dp 列表和检查器，输入法出现时尤其拥挤。

本次分配：

- 1200dp 及以上：预览 32%、列表 28%、参数 40%，同时工作。
- 700–1199dp：左侧 45% 为预览与列表上下分布，右侧 55% 为参数。
- 700dp 以下：列表与参数使用可切换主区，点字幕进入参数，正文关闭返回列表。预览可隐藏；工作区高度不足 500dp 时自动让位于编辑。
- 所有参数工具通过六个职责组和组内工具两级导航调用，避免十七个入口同时争抢一条导航。
- Canvas 初始尺寸按工具内容分配：事件结构和工程概况较短，时间轴较宽，样式、动画和批量规则有更大的初始编辑面积。只影响新窗口默认值，不改写已保存布局。
- 位置与几何拆为“位置与路径”“变换”“矩形裁剪”“Style 布局”。保留同一事件、同一语义模型及编辑变量，不把界面分区当成新的 ASS 数据对象。
- 帧时间和工程面板增加纵向滚动；帧模型与规则作用域的选项允许横向滚动，紧凑宽度下保持可达。

这些比例是可验证的初始布局，不是对每一种设备均已证实的最佳比例。不同 OEM 的输入法、字体缩放和导航栏仍需实机检查。

## 功能完整度

下表使用“闭环”“局部实现”“当前无入口”三种代码层状态，不使用缺乏统一分母的百分比。

| 能力 | 当前代码状态 | 证据与实际限制 |
| --- | --- | --- |
| ASS / SRT 打开、ASS 保存与 SRT 导出 | 闭环 | `AssCodec`、`SrtCodec`、ViewModel 与文件菜单；SRT 有表达能力损失，不能保留 ASS 全部样式 |
| 文本、时间、搜索、增删复制拆分合并 | 闭环 | `AssDocumentEditing`、正文/事件 UI；批量合并原先仅残留于未调用面板，本次移回实际批量工具 |
| Style 管理与主要排版字段 | 闭环 | `TypesettingPanel`；Style 影响所有引用者，Event override 优先级须继续明确显示 |
| Event 几何与动画 | 支持较广，非完整 ASS 标签覆盖 | pos/move/org/frz/fscx/fscy/fax/fay、矩形裁剪、fade、Transform；复杂片段语义和未知标签需要继续依赖保真测试 |
| 时间轴与帧时间 | 闭环但专业时间编辑仍有限 | 波形、拖动、吸附、CFR/VFR；轻量波形不是完整频谱/音节对齐环境 |
| Karaoke | 局部实现 | 已有音节时长和模式编辑；缺少成熟的分词与音频对齐工作流。初始化原先用 visibleText 清除标签，本次改为只接受纯文本并保留空白；有标签/转义时明确禁用自动初始化 |
| 矢量裁剪 | 局部实现 | 只编辑已有路径 token，画布用连线显示数字点，并非按 ASS 曲线命令精确渲染；无完整新建路径、节点拖动/曲线控制点编辑。标题与说明已纠正，不再称完整绘制或无损路径模型 |
| 字体 | 框架完整，需设备证据 | 导入、元数据、cmap 覆盖、绑定、依赖和 Fontconfig 渲染路线；资源存在不等于最终 font face 命中 |
| 质量检查 / 兼容性 | 已有闭环，规则非穷尽 | Linter、显式修复、配置档风险分析；不能把静态兼容性分析当实际播放器测试 |
| 双语校对 | 当前无产品入口 | `BilingualPairing`、`ReviewSidecar`、`ReviewEventKey` 仍在 core；当前 EditorState/ViewModel/UI 没有对应 Source/Reference/Final 工作区，不应称“已经提供双语校对” |
| MKV 读取与写回 | 闭环并有集成回归 | 选 ASS 轨、提取字体、替换 ASS、保留音视频；现有 fixture 不等于所有真实 MKV 均保真 |
| Undo / Recovery | 闭环 | 历史、临时预览、崩溃恢复；局部草稿与工程保存仍需覆盖跨工具/旋转/进程重建 |
| .asswb 工程 | 快照闭环、便携性不完整 | 文档、事件 ID、URI、选择与 Canvas 布局；不是包含视频/字体的自足工程包，跨设备 URI 不一定可用，固定布局局部 UI 状态未完整纳入快照 |
| 键鼠、无障碍、可配置历史与效率 | 需补充验收 | 存在基础控件但不能据此断言完整键盘操作、屏幕阅读器和用户可配置 Undo 步数全部完成 |

## 代码问题与本次处理

1. **重复旧面板**：`QcPane`、`BatchPane` 没有实际调用，当前分派使用 `AdvancedQcPane`、`RuleBatchPane`。本次删除旧实现，把已选字幕合并操作接回实际批量工具，避免两个实现长期漂移。
2. **导航知识重复**：工具名称原来只在主界面枚举中，目录没有职责与作用说明。本次提取 `WorkbenchToolCatalog.kt`，统一分类、描述和初始密度；保持全部已有 key。
3. **密集几何工具**：一个约六百行面板承载多类操作。本次先拆显示区；进一步应提取独立组件与 presenter，而不是继续增加同级字段。
4. **Karaoke 初始化丢失标签**：原实现先提取 visibleText 再写回，仅有纯文本被保留。增加明确领域策略和回归测试，含标签、注释、转义的文本不自动转换。
5. **能力表述过度**：已有矢量路径编辑器被描述为绘制/无损模型。本次纠正显示说明；未来确需完整路径保真与曲线渲染实现后才能恢复该表述。

## 可扩展性与优先顺序

**可保留的基础**：core/domain、core/fonts、core/container 不依赖 Compose；工具实例、绑定和 Surface 状态独立；ASS 是单一 canonical 文档，领域撤销与窗口操作分离；.asswb schema_version 有兼容入口。这些边界适合继续扩展。

**主要瓶颈**：主 UI 与 ViewModel 体积过大；当前工具内容分派是硬编码 `when`；只有 Style / Position 显式使用事件绑定，多数新工具仍依赖 focusedEventId。不能因为 Canvas 能复制窗口，就推断每个工具都支持独立 pinned target。目录元数据已经集中，但此次没有实现完整工具插件接口。

建议顺序：

1. 先完成本次导航与密度回归，验证草稿、横竖屏、手机/平板、输入法和 Canvas 旧布局恢复。
2. 为正文、事件结构、几何各子区、时间轴提取专用 UI 组件；ViewModel 分解文件 I/O、字体、预览、容器与领域命令。避免把页面拆分误当成业务模型拆分。
3. 扩充 ToolDescriptor，明确每个工具的对象、Binding 支持、作用域、可序列化 UI 状态、能力边界与测试入口；为焦点依赖工具补显式 target。
4. 恢复双语校对的产品入口，先稳定 Event ID 与 Reference/Final sidecar，再考虑多语言 Group。现有配对算法不应直接包装成完整多语模型。
5. 完善 Karaoke 与矢量裁剪的保真操作和精确预览；之后再补新建路径、音节对齐等高级交互。
6. 工程便携化需明确外部资源 URI 与可选复制策略，固定布局/选中工具/子区应有版本化 UI 状态。不能只扩展 JSON 字段而忽略 SAF 权限与资源生命周期。

完整 ASS 编辑器的扩展重点是局部修改不破坏无关语义、明确对象范围、可靠渲染与保存，不是仅增加更多标签按钮。
